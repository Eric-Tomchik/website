# Conventions & Patterns

> Code conventions, naming patterns, and best practices used in the codebase.

---

## File Naming
| Type | Convention | Example |
|---|---|---|
| Pages | `page.tsx` (Next.js App Router) | `src/app/about/page.tsx` |
| Layouts | `layout.tsx` | `src/app/admin/(dashboard)/layout.tsx` |
| Components | PascalCase | `BookCard.tsx`, `AdminSidebar.tsx` |
| Utilities | camelCase | `adminAuth.ts`, `sanitize.ts` |
| Convex functions | camelCase | `books.ts`, `blogPosts.ts` |

## Component Patterns

### Server Components (Default)
- All public pages are Server Components
- Data fetched with `fetchQuery()` at server level
- No `"use client"` directive

### Client Components
- Marked with `"use client"` at top
- Used for: interactivity, real-time data, browser APIs
- Examples: `CheckoutDrawer`, `CreditChecklist`, `SearchProvider`

### Admin Components
- Use `useAdminQuery()` and `useAdminMutation()` hooks
- Auto-inject admin API key
- Real-time subscriptions for live updates

## Styling
- Tailwind CSS utility classes (no CSS modules, no styled-components)
- `cn()` utility from `src/lib/utils.ts` for conditional class merging
- Custom `surface-*` and `brand-*` color tokens
- `dark:` variants for dark mode

## Data Fetching
| Context | Method | Library |
|---|---|---|
| Server Component | `fetchQuery()` | `convex/nextjs` |
| Client Component | `useQuery()` | `convex/react` |
| Mutation | `useMutation()` | `convex/react` |
| Admin query | `useAdminQuery()` | Custom hook |
| API route | Raw HTTP to Convex | `src/lib/convexRaw.ts` |

## Error Handling
- API routes return structured `{ error: string }` responses
- Convex functions throw for validation errors
- Client components use try/catch with toast notifications

## TypeScript
- Strict mode
- Types auto-generated by Convex (`convex/_generated/`)
- Props typed inline or via interfaces
